# crX

基于 [py-clash-bot](https://github.com/pyclashbot/py-clash-bot) 精简的《皇室战争》桌面自动化工具。
主要支持 Windows 上的 MuMu 模拟器，同时保留通用 ADB 设备连接。

## 运行停止条件

任务页的“运行控制”支持执行局数上限，以及“奖励领完后停止”（默认关闭）。
勾选后，每轮开始选择对战模式前检查主界面对战按钮上方的奖励栏：
连续两次确认空棕色栏内只剩皇冠时停止，不会开始下一局。
未识别到这一图示则继续按原流程运行；与局数上限同时使用时，任一条件满足即停止。
仅运行商店领取时不检查对战奖励；该功能也不代替商店领取或自动点击其他奖励。
两项配置均沿用本地 JSON 自动保存与启动恢复机制。
图示、检测范围和验证限制见 [奖励领完后停止](docs/reward-stop.md)。

## 环境与启动

使用 **Python 3.12 + uv**。依赖安装在本项目 `.venv` 内，不向全局 Python 安装包。

```powershell
Set-Location E:\MyWork\crX
uv sync --python 3.12 --locked
uv run python -m crX
```

`uv` 可管理独立的 Python 3.12 解释器；无需替换系统中已有的其他 Python 版本。

GitHub 自动检查配置保存在 [docs/ci/checks.yml.example](docs/ci/checks.yml.example)。
首次上传使用的 GitHub 凭证缺少 `workflow` 权限，因此暂以模板保留，未启用 Actions。
有相应权限后，将其放入 `.github/workflows/checks.yml` 并提交，即可在推送和 PR 时执行离线检查。

需要构建 Windows 安装包时，构建依赖也安装到本项目环境：

```powershell
uv run --group build scripts/setup_msi.py bdist_msi --target-version 0.1.0
```

## 使用 MuMu

1. 安装 MuMu，并在 MuMu 中创建一个实例。
2. 在该实例安装《皇室战争》，完成登录和教程。
3. 启动 crX，进入 **设备** 页，选择 **MuMu**。
4. 路径默认自动发现；查找失败时，可在 **高级设置** 中指定 MuMu 安装目录 / `MuMuManager.exe`。
5. 点击 **刷新设备**，选择已有实例的编号；**连接／检查** 用于验证启动、连接与截图。
6. 在 **任务** 页启用任务，然后点击 **启动**。

客户端固定为国服 `com.tencent.tmgp.supercell.clashroyale`，启动、停止和恢复均使用该包名。
国服中文界面已验证启动进入主界面及战后确认按钮，其他识别素材与完整对战流程尚未全部验证。
客户端选择规则与实机记录见 [docs/client-detection.md](docs/client-detection.md)。

MuMu 适配通过本地 `MuMuManager.exe` 查询和启动选定实例，并读取其实际 ADB 端口。
游戏控制统一使用 ADB：截图、点击、滑动和应用启动。一次只操作一个实例。
不创建、克隆或删除实例，不关闭其他实例，也不全局重启 ADB 服务。

首次开始任务会检查游戏是否安装，然后配置选定设备为 **720×1280（9:16）、320 DPI**。
游戏进入前台后检查实际截图尺寸。规则识别、模板匹配、点击、训练截图和录制直接使用原生 720×1280，不再缩小为 360×640。手牌按 108×132 原图统计指纹，保留已有参考库。
当前坐标、模板迁移及历史数据兼容说明见 [720×1280 原生匹配](docs/screen-720x1280.md)。旧采集批次和卡牌样本继续按原尺寸读取；不会改写原始数据。
现有模板由旧素材按二倍尺寸迁移，离线测试使用历史截图的合成 720p 回放。真实 720×1280、320 DPI 模板效果及全流程操作仍需实机校准。

**恢复默认分辨率** 可清除该设备的分辨率和 DPI 覆盖。

**通用 ADB** 模式要求用户自行启动设备并开启调试；多个设备在线或需主动连接时填写设备序列号或地址。
ADB 路径可指向 Android SDK 的 `adb.exe`，或留空使用 PATH 中的 ADB。

## 执行局数

在 **任务 → 运行控制 → 执行局数** 中填写本次启动要完成的对战数量。
`0` 表示不限，支持 0–10000；例如填写 `5`，各模式合计完成 5 局后自动停止。
仅在结算处理成功并返回主界面后计数，匹配失败、恢复重试、商店领取不计入。
**统计 → 已完成局数** 显示本次进度，关闭胜负统计不影响局数控制。
异常恢复保留当前进度；每次重新点击 **启动** 从零计数，配置的目标局数会保存。
仅启用商店领取时，该局数设置不限制商店检查。

## 保留功能

界面按“运行、设备、数据中心、设置”分组。任务配置与运行统计位于“运行”，
卡牌样本、异常流程和 YOLO 数据位于“数据中心”；顶部始终显示设备、当前步骤和完成局数。
卡组策略可单选当前卡组、随机或轮换，旧配置同时开启随机和轮换时仍优先轮换。

- Trophy Road、Classic 1v1、Classic 2v2，多模式按启用顺序轮换。
- 原有规则出牌、随机出牌及英雄/冠军技能触发。
- 任务页可勾选“使用表情”，默认关闭；勾选后，普通与随机出牌成功时以 10% 概率发送表情，设置自动保存。
- 从 1–10 号已有卡组中勾选参与卡组，保留点击先后顺序并自动保存。
- 随机卡组每局从勾选范围中随机选择；轮换卡组按勾选顺序循环，两项同时开启时优先轮换。
- 未勾选随机和轮换时使用游戏当前卡组；开启任一项时至少选择一套卡组。未满编或找不到的卡组会跳过，不自动修改卡牌。
- 每日商店免费领取，可单独启用；成功检查后每小时再检查一次。
- 胜负、胜率、出牌数、卡组与运行统计，本地日志。
- 可选对战录制、归档、自定义录制目录、存储大小查看和手动清理。
- GUI 主题和配置持久化。

设置中的“启动前同步卡牌数据”默认开启，关闭后直接使用本机已有参考库。
同步期间可点击顶部“取消启动”；程序会结束本次同步后恢复待机，不启动对战。
正在执行的 Git 请求会按原有超时边界退出，取消不会强行中断本地数据写入。

国服中文商店已补充“免费！”和“已收集！”识别、栏目滚动、免费确认及领取结果校验，
适配范围和实机验证记录见 [商店每日免费领取](docs/shop-daily.md)。

战后会逐页处理奖励宝箱和活动奖励，连续确认主界面稳定后再进入下一轮；
流程、超时边界及验证记录见 [战后奖励处理](docs/post-battle-rewards.md)。

战斗会自动记录未知／候选分数接近的手牌，战后生成待标注清单，
不改变配置的战斗次数。卡牌样本处理区使用“待确认、待更新”两个标签，人工核对后一次确认入库；已有正式参考覆盖时直接归档，不重复入库。
待更新列表可选中卡牌后点击“上传”，单独提交并推送正式参考指纹；成功后退出待更新列表，参考和原图保留在样本库。
右上角独立的“样本库”入口列出全部卡名、去重后的正式参考数量和可用缩略图，支持搜索、数量排序及单份参考原图查看。
其他机器更新代码后使用共享指纹；原始截图和备注保留在本机，无原图时明确显示占位提示。
操作见 [卡牌样本确认与入库](docs/card-trial-library.md)；采样限制与首批记录见 [卡牌采样与识别](docs/card-recognition.md)。

已移除卡牌养成、公主塔升级、部落操作、部落战、多账号、Discord，
以及 MEmu、BlueStacks、Google Play Games 的专用适配。

## YOLO 完整截图采集

进入 **YOLO 数据 → 截图采集** 页准备后续目标检测所需的完整截图。

1. 在 **设备** 页选好 MuMu 实例或 ADB 设备，将设备设为 **720×1280、320 DPI**，手动进入对战或回放。
2. 在 **YOLO 数据** 页选择保存目录，点击 **截取一张**，或设置采样间隔和张数上限后 **开始连续采集**。连续采集固定启用保守过滤：忽略顶部 HUD 和底部手牌，按原尺寸比较战场与上一张保留截图；2×2 的明显新目标会保留，无需设置开关。张数上限包含跳过的截图，结束时显示实际保存和跳过的数量。一批只采集一场，结束后停止。
3. 点击 **打开已有批次**，选择 `captures` 或其他采集目录，程序递归查找其中的批次，清理空批次文件夹，并按新旧名称中的采集时间倒序排列，自动载入最新的非空批次。找到多个时，可通过「找到的批次」下拉列表切换，选择后直接载入，无需额外点击按钮。也可直接选择具体批次文件夹。查找在后台进行，可停止，不会合并不同批次。空批次中若仍有未登记图片或其他文件，会保留文件夹并提示，不加入列表；普通非批次目录不会删除。
4. 采集、标注和训练直接使用完整 **720×1280** 截图，不再裁剪。页面仅保留完整截图预览，删除裁剪框和裁剪操作。
5. 点击 **筛选图片**，扫描当前打开的采集目录及子目录中的全部批次；未打开目录时使用「保存目录」。先按完整像素排除完全重复，再对战场像素相同但 HUD 不同的图片保留代表图；其他近似画面与已选代表图按内容比较，保留较清晰、有新增视觉信息的代表图；不同批次之间使用更严格的比较。筛选过程不删除原始图片。
6. 点击 **查看筛选结果**，选择相似分组后，以列表查看组内全部图片及「将导出／已筛除」状态，点击某张图片显示完整预览。程序按规则自动确定导出结果，查看列表不会改变选择；没有下拉框、保留勾选或手动调整选项。分组仅在分析时使用战场区域，导出仍是完整原图。算法按画面差异抽样，尚不能理解兵种和真实交战事件。
7. 点击页面底部的 **导出图片**，选择新的空输出目录，只生成 `images` 文件夹，精选完整图片直接平铺在里面，不预建标签目录、类别表或配置文件。文件名包含采集时间、稳定场次标识、原始帧号和导出唯一标识：同一批图片导出到不同新目录时也不会同名，后续合并文件夹无需重命名。再次导出到同一目录时按来源和图片像素跳过已有文件，保留原文件名，也支持停止后继续；已有未选中图片时要求更换空目录，避免旧图片混入，已有图片和标签不会删除。
8. 在外部工具中标注 `images`，再进入「标注与划分」按场次划分训练集／验证集。完全重复图片关联的来源场次会保持为同一组，防止去重后丢失关联而跨集合；近似候选不会因此合并来源场次。采集、删除或外部修改图片后，需要重新筛选图片。

筛选参考 [Ultralytics 数据采集指南](https://docs.ultralytics.com/guides/data-collection-and-annotation/) 中多样性与代表性原则，具体阈值属于本项目启发式，并非 YOLO 官方去重算法。保留决策完全基于内容，不使用每 3 秒补帧、末帧补留、时间间隔、分组时长或张数上限。1 秒和 3 秒采集的相同图片集合，筛选结果一致；文件中的时间仍作为来源信息保留。

相同内容优先选择战场拉普拉斯清晰度较高的原图。256 位感知哈希提供候选（距离最多 16）；每个哈希桶最多保留 64 个代表索引，每张最多复核 24 个候选，未命中时保守保留。最终在原尺寸像素和战场 SSIM（至少 0.90）上复核，不只凭大面积背景或哈希做排除。同场相似图必须直接匹配代表图，不使用上一张驱动的链式合并；跨场近似匹配还需通过严格局部像素变化检查。固定公主塔血量数字区域、微小目标、紧凑且单向的新增变化、较大整体差异优先保留。这些只是视觉启发式，尚不能识别所有兵种事件或保证类别均衡；不同皮肤与遮挡下仍需少量抽查，首版模型可用后再接入检测结果与主动学习。

图片特征和比较结果缓存在应用数据目录 `crX/filter-cache` 的 SQLite 文件中，不进入采集批次或 `images`。按原图路径、大小、修改／创建时间校验复用，内容哈希标识比较结果；新增、变化的图片重算，取消后可复用已算部分。缓存版本随规则升级区分；缓存损坏、不可写时自动退回直接分析，不影响原图和导出校验。再次筛选可复用特征与比较结果，新增或更清晰的代表图仍可能触发必要的原图复核。只读查看页列出全部组内图片及自动筛选状态，导出时仍检查来源与像素变化。

「上一张／下一张」旁的 **删除当前张** 只作用于当前采集批次；批次仍有图片时，文件移到该批次的 `.deleted` 中，删除后自动显示相邻图片。删除最后一张时，整个空批次文件夹及其 `.deleted` 暂存图片一起清理，并从列表移除，自动切换到其他已加载批次；没有剩余批次时清空预览。已导出、已标注的副本不联动删除。

新批次名称如 `2026-11-07_16-20-30`，同一秒再次创建时使用 `_02`、`_03` 顺序号。原来的随机尾段只是防止目录重名，没有业务含义；旧批次保留原名，新名称不再带随机尾段。文件名中的 `id` 用于区分同名场次，复制或重复整理后保持稳定。
导出文件名中的 `_export` 后是本次导出的唯一标识，使用完整 UUID；它只用于避免不同导出目录合并时重名，不参与场次划分。同一场的图片导出多次后仍归入同一场，旧文件名继续兼容。

截图默认保存到与 crX 工程同级的 `crX-data/captures`（例如 `E:\MyWork\crX-data\captures`），与标注目录 `annotated`、训练数据集目录 `datasets` 并列；打包版本使用应用目录同级的 `crX-data`，不受启动时工作目录影响。

保存目录右侧的 **打开** 按钮会直接打开当前填写的目录；不存在时先创建。需要更换位置时直接修改路径栏。

每批包含：

```text
<批次>/
  raw/000000.png       # 完整原图，720×1280
  metadata.json        # 图像来源、原始帧号、完整图像尺寸与场次编号
```

模型结果还原至完整原图后，坐标就是屏幕坐标，没有额外裁剪偏移。旧批次中的 `arena` 和裁剪元数据保留，仅供历史数据兼容。
保存 PNG 使用 BGR 图像无损编码，预览才转换为 RGB。其他尺寸不会自动拉伸。
采集期间可停止，已保存的数据保留；截图和文件处理在后台执行，自动对战与本页操作互斥。
采集只连接设备并读取截图，不重启或操作游戏。单位标注使用外部标注工具；完成后进入 **标注与划分** 子页。

## 标注数据导入与按场次划分

在外部标注工具中选择 **YOLO 目标检测** 导出格式，然后在 **YOLO 数据 → 标注与划分** 页选择标注目录。
数据可放在任意位置；点击 **打开默认导入目录** 会建立并打开 `E:\MyWork\crX-data\annotated`，附带导入说明。

整理阶段只生成图片：

```text
输出目录/
  images/
    2026-11-07_16-20-30-id场次标识__000000_export唯一标识.png
    2026-11-07_16-20-30-id场次标识__000001_export唯一标识.png
    2026-11-07_16-25-10-id场次标识__000000_export唯一标识.png
```

在标注工具中打开 images，使用完整原图标注，不要改动文件名前缀。
标注工具生成同名 YOLO txt，可直接放在 images，或放在根目录的 labels 文件夹中。
类别表使用标注工具导出的 classes.txt，可在载入时指定路径。
随后在「标注与划分」中载入包含 images 的根目录。平铺数据从文件名恢复场次，至少需要两场独立对局；同一场保持在同一集合。
旧 images/场次/图片 与 labels/场次/标签 格式仍支持单独载入，不与平铺结构混用。
类别表右侧的 **打开** 按钮会直接打开当前文件以便编辑；不存在时先创建父目录和空文件，已有内容保留。
平铺数据载入时检查完整截图尺寸，训练／验证集导出时附带输入配置。后续接入 YOLO 时直接使用完整截图和原图坐标；目前尚未接入模型推理或开始训练。历史 360p 批次继续可查看，但本方案的待标注导出要求 720p 原图。

输出目录右侧的 **打开** 按钮会直接打开当前目录；不存在时先创建。这两个按钮不弹出文件选择窗口。

划分以场次为最小单位，不将同一录像的相邻帧拆到两边；同一场的多个片段也必须放在同一场次目录。
至少需要两场独立对局。程序按整场图片数寻找最接近目标比例的组合，实际比例可能与设定值不同。
重复像素画面会去重并将关联场次合为一组；同画面标注冲突、缺少标签、类别编号或坐标无效时拒绝导出。
报告会列出训练／验证的类别目标数，提示缺少的类别；不会承诺少量场次下各类别均能覆盖。

输出默认位于 `crX-data/datasets/dataset-<独立编号>`，每次新建一份，源图片与标注保留：

```text
dataset-<编号>/
  images/train/       # 训练图片
  images/val/         # 验证图片
  labels/train/      # 训练标签
  labels/val/        # 验证标签
  data.yaml          # YOLO 数据集配置
  classes.txt
  split.json         # 来源、场次、去重、分配及复现参数记录
  划分报告.txt
```

修改比例、目录或类别表后需要重新载入；导出时会再次核对已载入图片和标签，变化则要求重新载入。
取消或失败会清除本次临时导出，不将未完成内容作为数据集发布。源目录不允许作为输出目录或包含输出目录。
输出用于 [YOLO26 目标检测训练](https://docs.ultralytics.com/models/yolo26/)，推荐起步模型 `yolo26n.pt`；训练数据格式见 [YOLO 检测数据说明](https://docs.ultralytics.com/datasets/detect/)。
本功能只准备数据，不安装训练依赖或启动训练；目前尚无实际标注数据，未开展真实训练。

## 录制与数据目录

仅录制 Trophy Road 和 Classic 1v1，不录制 2v2。
每局保存无损视频或 PNG 帧、`plays.jsonl` 和 `manifest.json`，保留原有 `pcb-pack/v1` 数据格式。
目标采样率为 3 fps，实际速率取决于 ADB 截图速度。
约 5 GiB 的散装数据会归入 ZIP；归档用于整理，并非显著压缩或限制总存储空间。
磁盘可用空间不足 10% 时跳过新录制。

运行日志保存在工程目录旁的 `crXlogs` 目录，与启动命令所在目录无关。
例如工程为 `D:\DaYe\crX` 时，日志目录为 `D:\DaYe\crXlogs`；目录在启动时自动创建。
日志按启动时间保存为 `.txt`，旧日志归档为同目录下的 `logs.zip`。
在 **设置 → 打开日志目录** 中可直接打开；修改日志路径后需重新启动程序生效。

恢复游戏前会尽量保存失败截图和诊断信息到 `crXlogs\failures`，
可在新增的 **异常样本** 页查看、放大、备注及标记处理状态，见 [异常样本说明](docs/failure-samples.md)。

Windows 的配置、卡牌样本和默认录制目录仍在 `%APPDATA%\crX`：

```text
crX/
├── user_settings.json
├── card_samples/
└── recordings/
    ├── <每局数据包>/
    └── zips/
```

配置和日志与原项目隔离，不读取旧版 pickle 设置。
胜负统计在点击战后“确定”前，匹配结算页双方皇冠上方的“获胜者”标记；不再打开对战日志。
连续两次识别结果一致才采用，短暂等待仍无法判断则记为未知，不计入胜负和胜率。
确认返回主界面后，未知结果仍计入已完成局数；返回失败仍走原有恢复流程。
胜负素材已补充 MuMu 原生结算页采集，胜利、失败各 4 帧及连续帧读取已验证；
完整自动对局的统计更新仍需后续运行核对。
Stop 使用操作系统终止工作进程，正在录制的一局可能留下未完成的数据包。
正常完成的对局会写入动作与结果；中途停止的包应视为不完整数据。
