# 执行局数

任务页的“运行控制”提供执行局数，配置键为 `max_fights`，默认 0（不限），允许范围 0–10000。
多种对战模式共享本次启动的局数，不按胜负分别计算，不限制商店领取次数。

`RuntimeContext.completed_fights` 仅在 `end_fight_state` 成功后增加，同时更新统计中的
`completed_fights`。它独立于商店与对战共同使用的 `completed_jobs`，也独立于胜负统计开关。
达到目标后工作进程正常退出，界面恢复“启动”，保留目标达成提示。异常恢复保留已完成局数，
手动停止后重新启动则重新计数。原有手动停止和连续恢复失败保护继续生效。

局数检查先于恢复处理，避免最后一局已经完成但录制归档失败时，再启动额外一局。
局数判断不依赖可能在结算前增加的各模式对局统计，也不依赖胜场与负场之和。

验证使用真实状态机与模拟游戏操作，覆盖输入边界、多模式合计、匹配／对战／结算失败重试、
商店不计数、0 不限、重新启动清零、归档失败时不多打一局、退出时保留目标提示。
本次不为验证局数而执行真实对战；完整实机限局流程尚未验证，已有 MSI 未重新构建。

验证结果：106 项离线测试通过，8 项完整实机用例默认排除，Ruff、格式和 ty 检查通过。
界面自动用例覆盖局数输入、统计显示和运行时禁用；解锁后已检查任务页的局数输入框、
说明文字与统计页的“已完成局数”，布局正常，没有文字截断。窗口保留在任务页，局数为 0。
