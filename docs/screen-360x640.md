# 360×640 / 9:16 画面适配

2026-10-19 起，运行画面统一为 **360×640、160 DPI、BGR**。MuMu 与通用 ADB 共用
`GAME_SCREEN_SIZE` / `GAME_SCREEN_DPI`；启动设置、截图校验、录制和新样本元数据使用同一尺寸。
运行时不会把任意分辨率的整张截图缩放后冒充原生画面，尺寸不符仍拒绝启动。

## 坐标和素材

- 出牌坐标、通用区域、滑动距离和旧像素检测以 `x × 360/419`、`y × 640/633` 四舍五入迁移。
- MuMu 原生画面证明：固定 160 DPI 后，许多按钮、文字、手牌图案保留像素大小，只改变位置。
  因而主界面、模式按钮、卡牌页、商店、手牌和圣水条按原生布局校准，不能机械拉伸这些图案。
- 手牌图案仍为 **54×66**，四个左上角变为 `(85,536)`、`(152,536)`、`(219,536)`、`(286,536)`。
  指纹仍为四象限、每象限 891 像素的 16 色计数，原库和本地已补库指纹不改写。
- 模板包含迁移后的比例版本、固定 DPI 下可复用的原尺寸图案（`fixed_dpi` 后缀），以及实际采集的
  `zh_cn_360` 版本；不降低原有匹配阈值来掩盖位置或素材错误。
- 战斗识别使用面板外侧固定边框，避免手牌变灰、发光导致提前退出；活动量按采样面积归一化，
  圣水等待阈值、槽位选择和卡牌分组保持既有策略。

## 历史数据与验证素材

磁盘中的 419×633 卡牌样本、标注和补库文件不迁移、不覆盖。查看、标注、导出和本地补库仍可
读取旧画面，并使用旧手牌裁切位置；新采样、录制及出牌坐标使用 360×640。

`tests/fixtures` 中原有画面已制作成新尺寸的比例回放数据，手牌回放保留原尺寸卡图并移动到新槽位；
这些是合成迁移样本，文件名中的旧 `native` 表示来源，**不代表新尺寸实机采集**。
原始数据可从 Git 历史恢复。

新增 `*-360-native.png` 来自 Android 15 的 MuMu 实例1真实截图，仅保留识别所需区域，遮去账号等信息。
`hand-legacy-419.png` 则专门保留旧尺寸，用于验证旧样本可继续导出且原图不变。

实机已验证启动、主界面、空奖励栏、三种模式的切换与图标、卡牌页、商店每日精选的已收集状态、训练场手牌及圣水、
训练结算确认。经典 1v1 完整执行 104 秒、9 次出牌，持续到真实结算，识别为失败并返回主界面，
未触发恢复；诊断直接调用战斗函数，不经过 worker 的局数状态，因此不把诊断统计写入持久化配置。
胜利结算、2v2 完整对战、未领取免费商品和所有战后奖励动画尚未在新尺寸实机逐项验证；
比例回放通过不能代替这些场景的实机验证。
