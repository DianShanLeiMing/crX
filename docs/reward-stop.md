# 奖励领完后停止

“任务 → 运行控制 → 奖励领完后停止”默认不勾选；勾选后与执行局数上限共同生效。
用户设置保存在 `%APPDATA%/crX/user_settings.json` 的 `stop_after_rewards` 布尔字段中。
旧配置缺少该字段时使用关闭状态，实例编号、执行局数和其他已有值不被重置。

## 判定与停止

按用户提供的含义：主界面对战按钮上方的空棕色奖励栏，内部只显示一个皇冠，表示奖励已领完。
当前 MuMu 实例恰好也显示此状态，因此模板直接取自原生 419×633 截图，未使用缩放附件。
空栏模板为 `battle_rewards_finished/zh_cn_1.png`，裁剪范围 `(154, 405, 267, 447)`。
皇冠会浮动并轻微转动，因此模板及待检测画面均将 `(194, 385, 230, 443)` 动画区域遮黑，
先验证固定空栏，再使用 `battle_reward_crown/` 中的两张原生局部图验证皇冠。

同一张画面须先通过现有主界面像素检查，再在 `(135, 390, 285, 455)` 内匹配空栏，阈值 0.96；
皇冠在 `(185, 385, 235, 448)` 内搜索，阈值 0.9。只有空栏背景和皇冠同时成立才确认。
每轮选对战模式前检查，两次检测间隔 0.4 秒，均命中才正常停止并保留停止原因。
奖励未完成、画面不匹配或单次瞬时命中均不会推断为已领完；不会在战斗中检查或中断对局。
成功完成一局后，现有流程返回主界面并计入局数，下一轮再检测奖励栏。
局数先到上限仍按原逻辑停止；只有商店任务时继续按原间隔领取，不受此选项影响。

该功能仅检测用户指定的奖励结束图示，不点击奖励栏，不负责领取其他奖励。
按钮下方的 `5/500` 等皇冠进度不作为停止依据。

## 验证

151 项离线测试通过，8 项完整实机测试默认排除；Ruff 检查、格式检查和 ty 类型检查通过。
新增覆盖：真实原生空栏及浮动皇冠、仅空栏/仅皇冠的反例、未完成奖励栏、非主界面、错误分辨率、布尔校验、旧配置兼容、
首局前停止、完成奖励后不再开局、局数优先、关闭选项、瞬时命中、仅商店及停止原因保留。
配置开关在 GUI 冒烟测试中验证了读写及运行时禁用；解锁后使用独立界面预览核对了
任务页布局、勾选状态、运行时禁用和停止后恢复，显示正常，无截断或重叠。
预览未启动对战工作进程；检查前后本地配置文件 SHA-256 一致。

原生空栏来自当前选定 MuMu 实例的只读截屏；未完成奖励的反例来自已有真实主界面截图的奖励区域。
回归截图仅保留检测区和主界面判定用的少量像素，遮去玩家名称和资源数值。
原始实机截图仅保存在已忽略的 `docs/reference/`，不进入 Git。
这验证了当前结束图示的识别，尚未真实运行从奖励未完到领完的完整对局流程，其他界面版本亦待实机验证。
