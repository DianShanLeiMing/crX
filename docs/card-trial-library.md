# 卡牌补库

流程：**发现未知 → 确认卡名 → 本地试用 → 运行观察 → 人工确认正式补库**。

确认普通、觉醒或精英版本后点击“确认”，单份有效手牌样本即可使用，不要求其他对局的同名样本。
原始截图不修改，人工标注单独保存在 annotations.json。运行预测不会自动变成人工标注。

## 页面操作

| 选项 | 操作 | 含义 |
| --- | --- | --- |
| 待确认 | 确认 | 为选中样本指定准确卡名并自动启用 |
| 补库 | 确认正式补库 | 每卡汇总尚未正式补库的新参考，只纳入符合建议条件且经人工核对的参考 |
| 全部 | 确认／更正卡名 | 选择具体样本纠正误标，系统撤销错误来源关联并检查冲突 |

所有列表支持按需选择、多选、全选、取消选择和清空选中，运行时禁用删除。
补库汇总中清空一种卡牌只删除该卡尚待正式补库的本地候选，包含本地试用指纹；确认框列明范围。
已经完成正式补库或被正式库覆盖的参考退出候选，其原始截图、标注和本地记录保留在“全部”中，不随新候选清空。
“全部”中的处理状态补充具体原因，例如“已忽略，正式库已有相同或近似参考”、
“已忽略，已合并到同卡近似参考”或“已忽略，切牌动画”（手动备注）。
手动忽略未填写备注时明确显示“已忽略，手动忽略，未填写原因”；长备注在状态列简写，说明及原备注保留完整内容。
这些说明只解释候选为何不单独处理，不撤销原有人工卡名，也不停止被多个来源共用的有效参考。
已经正式纳入的内置参考保留。页面不再提供启用、撤销按钮；历史停用或补库失败的样本可在“全部”中重新确认卡名。
未知历史样本不会因后续识别成功而自动删除或自动确认，可自行确认或清空选中项。

## 同卡多份外观

同卡同版本最多启用8份不同指纹；普通、觉醒、精英分别管理。图像指纹距离不超过100的同卡样本合并来源，
外观差异较大的样本同时保留。识别时从原库与所有已启用指纹中选最近者，沿用1000距离阈值。
计算候选间距时先按卡名去重，同卡不同外观不会被当成两个竞争卡名。
不再计算综合评分或按最高分只选一个外观，原库已能识别也不会阻止人工补库。
达到8份上限时保留已确认标注并提示整理，不静默删除有效指纹。

## 运行观察与复核

补库表显示卡名、样本参考数、补足识别次数、正式补库、说明和缩略图。
多个样本来源合并为一份指纹时，数量和补足次数只计一次。
“样本参考数”指去重后尚待正式补库、参与本地试用的外观数量，不是人工确认的原始样本条数。
样本参考数、补足次数和纳入建议均不包含已经被正式库覆盖的历史参考。
说明中的“本地试用中”表示已经参与识别，没有自动判定验证通过的步骤。已由正式库覆盖的历史参考可在“全部”中查看。

点击补库汇总中的卡牌，下方默认打开“参考样本”页，每份去重后的指纹各占一行，
显示缩略图、自己的补足识别次数、对局数、纳入建议和来源编号；行内提供“修改卡名”“删除”，按钮文字统一为白色。
例如电击法术有3份参考时，下面显示3行，各自的补足次数不混用。
补库模式默认打开“参考样本”，旁边保留“手牌与识别信息”“完整战斗截图”标签页。
点击某份参考的缩略图或文字选中该行，再切换上述标签查看对应内容；行内不增加“详情”按钮。
尚未点击具体参考时默认选中第一份；刷新保留当前参考和已打开的标签页。
补库模式不提供统一的“确认卡名”“处理备注”输入框，待确认及全部页面的原操作保留。

“修改卡名”支持中文、英文及关键词搜索，校验普通／觉醒／精英版本，沿用确认卡名并自动补库的流程。
一份参考合并了多张来源时，更正会作用于其全部来源，保留每张来源原有备注；同卡其他参考不变。
“删除”经确认后只删除该参考及关联来源截图、标注和运行记录，同卡其他参考及正式库保留；运行期间禁用删除。
提交前重新检查参考编号、卡名和来源集合，参考已变化时要求刷新后重试，避免操作过期的行。

每次识别复用同一份手牌指纹，同时比较“仅正式库”和“正式库＋本地参考”的结果，不额外截图。
正式库包含 Python 原始参考、内置外观及随程序分发的补充 JSON，不包含任何本地候选。

| 仅正式库 | 加入本地参考 | 处理 |
| --- | --- | --- |
| 未知 | 特斯拉电磁塔 | 本地参考的补足识别次数＋1 |
| 特斯拉电磁塔 | 特斯拉电磁塔 | 已有覆盖，不计补足 |
| 其他卡名 | 特斯拉电磁塔 | 不计补足，保留“正式库与本地识别不一致”样本供人工核对 |
| 未知 | 未知 | 不计补足，沿用未知样本采集 |

同一手牌位置连续显示同一卡名时，定期观察、出牌前识别、短暂未知及同卡不同指纹胜出均不会重复增加补足次数。
观察到该位置换成另一张已识别卡牌后，才开始新的计数机会；未观察到换牌时保守地不重复累计。
每份参考在同一局无论补足多少次，对局数只增加一次，后台刷写不会重新计局。
补足计数不影响现有识别阈值、选牌和出牌策略；没有补足记录不等于样本无效，不会因此停用。
后台约每5秒保存运行统计，界面约每5秒刷新，结束对局也会刷写剩余统计。
距离过大或不同卡名候选过近时保留复核截图，其他有效指纹继续使用。
识别不一致样本不会被原有相似图片过滤吞掉，每份参考与正式库卡名组合保留一条报告。
有尚未核对的不一致报告时暂不建议正式补库；在“待确认／全部”中确认与本地参考相同的卡名后重新评估。
如果确认成其他卡名，该参考仍暂不建议，应检查并清理或更正原参考。

如果不同人工卡名对应近乎相同的指纹（距离不超过100），相关指纹停用并显示“需复核”，
说明列出冲突卡名。到“全部”中更正具体样本后重新检查；冲突解除可恢复，人工明确撤销项仍保持停用。
补足识别次数、距离和间距用于观察，不宣称自动证明卡名正确。

## 正式补库

补库页只管理新参考，“正式补库”列仅显示“建议纳入”“暂不建议”。每份参考分别判断：人工确认有效、
补足识别至少100次、来自至少3个对局、补足记录的平均不同卡名候选间距至少100，
且无已知卡名冲突或未解决的识别不一致报告、未被同卡内置参考覆盖。
100次与3局是建议门槛，仍需人工核对，不是正确率保证。
一张卡的汇总补足次数不会让尚无有效记录的其他外观一起达标；各份参考的次数和建议显示在下方“参考样本”中。
同卡有新参考达标时显示“建议纳入”，否则显示“暂不建议”；只有达标的具体参考会进入人工确认弹窗。
正式补库完成或与正式库同卡参考距离不超过100时，该参考退出候选，不重复追加模板。
若仍有同卡其他候选，保留该行并只统计剩余候选；全部完成时该行退出补库页。
同卡后续新外观独立积累补足次数和对局证据，历史正式补库记录不影响其建议，不继承历史次数。

停止任务后选中卡牌，点击“确认正式补库”，核对弹窗中的卡名、版本、截图、补足次数、对局数和匹配情况，
再点“确认加入内置库”。只有弹窗列出的参考会处理，确认前重新检查标注、运行记录和冲突。
补足次数不能视作正确率；此操作表示用户已核对实际识别结果。一次最多64份，近似参考去重。

源码运行时更新项目的 `crX/bot/card_reference_library.json`，无需手写Python；项目文件可随commit提交，
构建后随程序分发。内置库仅保存卡名与指纹，不包含截图、玩家信息或对局路径。
安装版或项目文件无写入权限时，生成本地 `card_samples/formal-library-export.json`，需合入项目后再发布；
仅导出时仍保留本地候选，也不会自动加入当前安装版的内置库。
运行端约每秒刷新内置补充库；文件损坏时保留原有识别库的正常使用。
清空本地样本、标注和本地指纹不会删除正式库；更正或移除正式参考需修改项目内置文件。

## 本地存储与兼容

使用原有 %APPDATA%/crX/card_samples 目录与原子JSON；无网络服务或新增依赖。
库格式更新为version 2，首次改写旧格式前保留 fingerprints-before-multi.json，运行计数和原始标注不清除。
runtime-matches.json 保留原有 matches、distance_total、margin_total 历史观察字段，
新增 assists、assist_battles、assist_distance_total、assist_margin_total 独立保存补足证据。
历史命中无法还原当时正式库结果，不折算为补足次数；升级后新计数从0开始，不影响已正式纳入的参考。
历史trial、covered及active记录只要来源人工标注仍有效且无冲突，即按新规则启用；
历史disabled记录保持停用，可在“全部”中重新核对并确认卡名。每卡数量、全库大小、源文件与路径检查仍保留。

回归覆盖单份确认立即识别、多外观共同识别、版本分离、重复来源去重、8份上限、
人工更正与冲突解除、明确撤销、运行统计、选择性清空、损坏记录拒绝覆盖及界面操作。
