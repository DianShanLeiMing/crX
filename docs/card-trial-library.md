# 卡牌样本确认与入库

流程：**发现异常样本 → 人工核对卡名及版本 → 确认并入库 → 系统归类**。

处理区保留两个标签：**待确认、待上传**。样本库作为页面右上角的独立查询入口。“待上传”是已在本机正式生效、尚未共享的参考，按卡名合并为一行。
待上传标签按卡牌种数统计，待确认按来源样本张数统计。正式库已覆盖的样本确认后移出待确认，不再单独展示或统计。
点击待上传卡名，下方展示框默认列出该卡各份未上传参考的缩略图和入库说明。
头部通过“参考列表／手牌与识别信息／完整战斗图”切换内容，选择具体参考后点击详情入口才加载对应内容；
切换卡名返回参考列表，可针对选中参考更正或移出。
上方卡名列表和下方参考列表均采用紧凑缩略图与文字；上方不再显示说明列。
两区之间保留可拖动分隔边，不额外显示文字提示；第二个展示框底边也可上下拖动，调整自身高度并保留上方列表高度。
分隔边使用加宽的拖动区域与上下调整光标；手动调整后，提示内容变化和刷新列表不会将区域高度重置为默认值。
底部操作区可滚动，不以全部控件的高度限制展示框下拉；空间不足时可滚动查看操作控件。
多个来源可以关联同一份去重后的正式参考，展示框按参考去重。
入库说明统一显示“已加入正式库”，不区分首份和补充参考；全部正式参考按相似度共同判断卡名，再按该卡的参考顺序采用首个达标参考。
历史入库说明同步统一，保留人工备注。
待确认和待上传阶段保留原始截图；人工卡名、备注、处理结果和正式参考编号保存在各对局的 `annotations.json`。

## 样本库查询

点击右上角“样本库”进入独立查询视图，隐藏处理标签和编辑工具；点击“返回样本管理”回到进入前的处理标签。
样本库采用左右布局，不再叠加上下处理区域。左侧每卡一行，显示卡名、正式参考数量；
列出所有已知卡名，普通／觉醒／精英版本分开，未收录正式参考的卡牌显示0。
支持中文卡名和英文ID搜索、“只看有样本”筛选；点击样本数表头切换数量降序／升序，点击卡名表头恢复卡名排序。
右侧列出所选卡牌的全部正式参考，展示参考名称、参考编号和命中数，不加载原图或对比图。
每卡最多一份“首选”，其余为“参考1、参考2……”；原内置来源附加“（内置参考）”备注，位置变化不改变来源。
第一份原内置参考默认首选，其余原内置参考依次编号；没有内置参考的卡牌由用户主动指定首选。
选中参考后“设为首选 / 交换”：没有首选时直接设置，已有首选时交换位置；指纹编号、命中数和来源备注保留。
首选固定第一，普通参考可直接上下拖动，松开后保存顺序；拖动不会改变编号、来源备注和命中数，Esc取消拖动。
未手动排序时按命中数降序，同数按固定序号；手动排序后以保存顺序为准，刷新、重新打开和命中数变化均不覆盖手动顺序。
首选通过“设为首选 / 交换”调整，不能拖离第一行；任务运行时禁止排序。手动顺序随所选卡牌的配置上传共享。
运行时先用所有参考的最小距离判断卡名与候选分差，再在该卡中按“首选→保存后的普通参考顺序”采用首个距离不超过1000的参考。
排在前面的参考不达标则继续下一份；命中数记给实际采用的参考，不因其他卡牌较早达标而跳过更相似的卡名。
诊断记录的候选距离保留卡名最佳匹配值，`reference_distance` 单独记录实际采用参考的距离。
样本库不展示上传状态；尚未共享的参考仍在“待上传”处理。
图库中不显示确认卡名、备注编辑和删除操作；任务运行时可查询，不能修改首选、清空统计或上传。
数量合并内置指纹、原有变体和JSON正式参考，按同一卡名及指纹去重，不把采集重复来源重复计数。
确认入库后立即进入样本库；上传成功后移除对应卡牌图、手牌图、战斗图，正式参考与人工备注保留。
历史已上传记录同样清理，必须有有效指纹和上传记录；清理中断可刷新重试，待确认及未上传图片保留。

## 命中累计与数据保存

同一战斗、同一手牌位置连续出现同一卡牌，只给首次有效识别采用的参考累计一次。
重复帧、短暂未知及同卡切换参考不重复计数；该位置出现其他卡牌后再次出现或新战斗可重新累计。
未知和未采用的候选不计数。原内置与后续参考口径相同；次数代表使用频率，不代表正确率，不自动更换首选。

原始指纹迁入 `crX/bot/card_builtin_references.json`，后续指纹保留在 `card_reference_library.json`；
两者使用同样的稳定编号、卡名和4×16指纹字段。Python保留卡名、出牌配置和算法。
`card_reference_preferences.json` 保存固定序号和每卡首选；来源备注由原始指纹库确定。
`card_reference_hits.json` 保存共享命中统计，本地累计保存在样本根目录的 `reference-hits-local.json`。

运行和清空仅改变本地统计，清空不自动勾选上传；拉取有更新的远端统计可以覆盖本地清空。
上传时只有明确勾选“更新命中数”才包含统计，包含清空结果时页面明确提示。
各电脑使用随机统计节点，按节点合并累计值，重复上传不重复计数；共享清空使用新统计代次，旧电脑的旧次数不能恢复进来。

## 上传到其他机器

本机确认入库会更新项目的 `crX/bot/card_reference_library.json`，提交并推送后其他机器更新代码才能获得这些参考。
工具栏的**上传**按钮用于共享正式参考：在待上传列表选择一张或多张卡牌，上传这些卡牌尚未共享的正式参考。
“删除样本”单独放在工具栏最右侧，与上传和常用选择按钮分开，删除仍需确认。
上传追加所选卡名、参考编号和指纹，并同步所选卡牌的首选与序号配置；命中统计须主动勾选。
不包含截图、对局记录或人工备注，也不自动同步删除。
推送成功后按参考编号记录已上传状态，从待上传列表归档；推送失败保留待上传，不把本地提交当作已共享。
同卡新增参考使用新编号，会再次进入待上传；原来上传过的参考继续留在样本库。
旧记录用本机已获取的远端跟踪版本核对并恢复归档，不在定时刷新时联网获取；Git不可用时仍可查询样本库和本机上传记录。
其他机器更新代码并重新运行后，参考直接参与正式识别；样本库能显示其卡名、数量、首选以及已共享的统计。

上传前运行 Ruff 和类型检查，创建仅包含所选参考及配置 JSON 的独立提交，再推送到当前分支配置的跟踪远端。
未选参考和其他未暂存的代码改动保留在本地；已有暂存改动或未推送的其他代码提交时提示先处理，不混入上传。
远端已更新时提示先更新代码，不自动合并；推送失败保留本地提交，再次上传可继续推送，不重复创建相同提交。
源码项目需已配置 Git 身份、分支跟踪和推送凭据；操作在后台执行，上传期间禁用修改和启动任务。

## 一次确认

在“待确认”选择样本，搜索准确卡名，核对普通／觉醒／精英版本，点击“确认并入库”。
候选名称只作提示，不会自动填写为人工标注。

| 检查结果 | 处理 |
| --- | --- |
| 正式库已有同卡近似参考，或已能正确识别且候选差距足够 | 提示正式库已覆盖、无需入库，关联现有参考并移出待确认 |
| 现有库未知、误认或候选过近，样本有效且无已知冲突 | 成功写入正式库后进入“待上传”，同时纳入样本库 |
| 与其他人工卡名或正式卡名的指纹过近 | 留在“待确认”，显示“需复核”和具体冲突卡名 |
| 图片无效、容量超限或写入失败 | 留在“待确认”，显示原因，保留已选择卡名及备注，可重试 |

同卡近似去重、跨卡名冲突沿用100距离阈值，运行识别阈值仍为1000。
新增前再用当前正式库判断一次：卡名正确、距离不超过运行阈值1000，且与其他卡名的候选间距至少100时，
直接记录覆盖结果并移出待确认，不重复入库。同卡多个外观不作为互相竞争的候选；本批刚加入的参考也参与后续样本判断。
普通识别不一致供人工核对，不直接等同于近似指纹冲突。

不再经过本地试用、补足100次／3个对局、第二轮正式补库确认。
历史运行记录保留供观察，不构成入库条件或正确率保证。
一次最多处理64张样本；同批样本也会去重，逐项汇报已入库、已被覆盖、需复核和检查失败数量。

## 处理区操作

- **待确认**：确认并入库；无需保留的样本选中后通过“删除样本”处理。冲突仍留在该标签，优先展示。
- **待上传**：更正卡名、移出正式参考和上传。更正或移出针对选中的同一份参考，影响全部关联来源。

“待确认”直接展示全部待确认样本，不再提供“全部分组”或相似组下拉筛选。
列表保留相似组提示、选中本组、多选、全选当前列表和取消选择；“X 张”仅统计该组待确认的样本。
多选确认时，全部选中样本使用同一卡名、版本及备注。
待上传按卡名汇总。独立的样本库视图提供查询、搜索、数量筛选和单份参考查看，不提供删除操作。

页面分组与采集去重独立：有效单卡样本如已有名录中的相同人工卡名及版本，优先归入同一组，
允许同卡不同姿态和外观一起查看；不同人工卡名或版本保持分开。没有人工卡名的样本先进行形状哈希／颜色比较，未匹配时允许在54×66卡图上
进行最多横向8像素、纵向6像素的平移对齐，双向结构相关度至少0.78，且对齐后的平均颜色差不超过24。
平移比较使用中部卡图，减少边缘动画的影响；图像比较仍直接对照组代表图，不进行链式合组。
候选卡名不决定分组；无效图片即使具有相同人工卡名也保持单独分组。
同卡页面合组不会合并或删除各份正式参考，正式库仍分别检查和保存有效外观。
相似组仅辅助查看和多选，批量确认前仍需逐张核对卡名与版本，不会自动标注或自动入库。
采集端继续使用原来的保守去重规则，页面合组不会丢弃原始样本或修改采样频率。

列表突出较大的卡图、卡名／候选提示、采样原因及处理结果；对局路径在详情中查看。
详情保留卡牌裁图、手牌与识别信息、完整截图和参考对照。
正式库本身只保存颜色指纹，存在关联来源时展示真实参考裁图；没有原图时明确说明，不生成替代图。

## 更正、移出与删除

**更正卡名**同步更正本流程加入的正式补充参考及其全部关联来源，保留各来源原备注，重新检查冲突和去重。
若更正后与已有同卡参考重复，关联现有参考并归档；存在冲突时保持原参考并提示原因。

**移出正式参考**经确认后删除选中的一份正式补充参考，全部关联来源恢复待确认，保留图片和备注。
程序原始Python参考和固定外观不通过样本操作修改。

**删除样本**只清理选中记录、截图、标注及关联本地历史记录，已写入的正式参考保留。
删除与移出使用不同按钮和确认说明；删除样本不可撤销。
已清空来源的正式参考仍保存在项目补充JSON中，后续可通过项目文件维护。

任务运行时可查看与切换标签，确认、更正、移出和删除均禁用。
后台操作期间禁止启动任务；提交前重新读取样本与标注，过期选择要求刷新重试。

## 历史数据与写入

旧记录按实际结果归类：已正式纳入、尚未确认上传的参考归“待上传”，已上传的仅在样本库中查询；已有正确识别覆盖的样本保留内部覆盖记录，不再展示，
历史已忽略记录保留在本地，不再提供忽略、已忽略或恢复入口；不自动删除，也不重新放回待确认。
只有历史卡名／本地试用而未正式入库的归“待确认”，保留卡名和备注。
迁移不把旧试用候选自动加入正式库；这些待确认来源不继续作为有效本地试用证据。

首次停止任务时会按新的覆盖规则重判历史数据。已确认新增的旧参考，只有其全部关联来源都能被其他保留参考接替时才移出，
关联样本记录覆盖结果并归档，不再展示；逐份处理，避免互相覆盖的参考被一起移除。原有正式参考保留，入库说明统一显示“已加入正式库”。
调整前在本地保存 `formal-before-coverage.json`，截图、卡名和用户备注保留。
处理结果显式保存，重判完成后不重复执行；判断历史参考是否可替代时排除它自身。
正式参考被移出后，关联样本返回待确认。

源码运行时更新 `crX/bot/card_reference_library.json`，运行端约每秒刷新。
正式库仅保存卡名与颜色指纹，不包含截图、对局路径或玩家信息。
当前安装版不能直接更新内置正式库；没有可写源码项目时，保留待确认并明确提示，导出文件不冒充入库成功。

沿用原子JSON写入和容量限制；使用进程间写锁及提交前版本比较。
正式库与来源标注的更新由本地 `card-review-transaction.json` 记录；部分写入后可在下次刷新恢复。
恢复时如发现其他窗口修改了正式库或标注，则停止并提示人工检查，避免覆盖并发更新。
文件扫描、图片读取和写入在后台完成，Tk控件只在主线程更新。
