# 补库与自动择优

流程：**确认卡名 → 自动离线验证 → 合格候选中选最高分 → 运行观察**。
核对普通／觉醒／精英版本后点击“确认”，自动加入候选并离线验证，不再需要点击“试用”或“补库”才能完成选用。
每个卡名和版本最多启用一个补库指纹；没有合格项时只使用原库，不加载未合格候选。
按钮按筛选显示，支持 Ctrl / Shift 多选：

| 筛选 | 按钮 | 操作 |
| --- | --- | --- |
| 待确认 | 确认 | 确认后自动加入离线验证并择优 |
| 补库 | 重新验证、撤销 | 每个卡名及版本只显示一个结果；撤销该卡全部候选 |
| 全部 | 无阶段按钮 | 查看所有原始记录 |

所有筛选共用“全选当前列表”“取消选择”“清空选中”，也支持 Ctrl / Shift 多选与 Ctrl+A。
没有直接清空全部数据的按钮；需要先选择，再确认删除范围。

后台会持续复核评分和证据，无需手动“验证并保留”。“重新验证”立即复核已有证据，
不会跳过验证要求；证据不足时保持未启用。已选用条目支持撤销，撤销项不自动重新启用。
筛选项只保留“待确认、补库、全部”，没有“已确认”中间步骤或“加入验证”按钮。
历史确认、撤销、加入候选失败的记录都归入补库汇总；可以直接点击“重新验证”加入候选并复核。
撤销项只在用户明确点击“重新验证”时重新加入，普通后台刷新不会恢复撤销项。
单卡候选数量达到上限或素材有误时，卡名和备注仍保留，处理问题后可在补库页重试。

## 补库页按卡名汇总

“补库”每个卡名及版本只显示一条结果，不受相似分组限制；该页禁用相似分组筛选和“选中本组”。

| 补库结果 | 评分 | 说明 |
| --- | --- | --- |
| 当前使用 | 当前选用指纹的综合评分 | 展示实际采用的样本，不会被高分但不合格项替代 |
| 暂无可用补库 | — | 展示未启用的具体原因，例如缺少另一对局的同卡样本 |
| 原库可识别 | — | 原库已覆盖，无需重复补库 |

该页只显示卡牌名称、补库结果、综合评分、验证说明和运行记录，不再逐条列出未使用候选。
选择汇总行仍可查看代表样本的截图。当前选用变化后，选中项按卡名跟随新的代表样本。
其他候选保留在后台；“全部”仍可查看原始记录、相似分组和每条验证详情。

## 原始记录的验证信息

原始记录中验证与选用分列显示，不使用“已补库”等混合状态：

| 列 | 显示 | 含义 |
| --- | --- | --- |
| 验证状态 | 未验证 · 待确认 / 未加入验证 | 尚未加入候选验证 |
| 验证状态 | 证据不足 / 无新增覆盖 | 当前不满足条件，不表示有等待执行的验证任务；原因见验证说明 |
| 验证状态 | 离线验证通过 / 离线验证未通过 | 人工确认截图的验证结果；未选中的合格候选也显示通过 |
| 验证状态 | 验证记录不足 | 历史已选用项缺少充分验证记录，不推定通过 |
| 验证说明 | 缺少同卡样本 / 独立样本未命中 / 缺少其他卡牌对照 / 没有增加识别覆盖 / 误认 | 说明未合格原因；通过时显示正确命中、新增覆盖与误认数量 |
| 运行记录（未核验正误） | 无匹配记录 / 匹配 N 次 · 未核验 | 是否在运行时匹配过该指纹，不表示识别正确 |
| 选用结果 | 当前使用 / 未使用 | 仅说明程序当前是否采用该补库指纹；验证结果及未使用原因看前两列 |

目前没有自动记录“人工实战核验通过”的机制，所以不会显示“实战测试通过”。
不再单独显示“备用”；未使用的候选仍保留，重新择优时可继续采用合格项。
原始记录每个相似组内按综合评分降序排列，无评分的排最后，同分保持原有顺序；分组顺序不变。
不再显示“待验证”或编号，只展示本轮评估结果和具体说明。
后台统一评估候选并按合格最高分选用。原库能够识别的样本显示“原库已覆盖”，表示无需重复补库。

筛选项为“待确认、补库、全部”。已正式选用、历史确认及原库已覆盖的记录都归入“补库”，
移除“已补库、无需补库、已忽略”独立筛选项。历史忽略记录仍可在“全部”中查看，选中后清空。

## 评分与选用

原始记录显示“验证状态”“验证说明”“综合评分”“运行记录（未核验正误）”“选用结果”。
评分满分 100：独立人工标注样本的匹配质量占 70 分，实际运行平均匹配质量占 20 分，
独立正样本覆盖数量占 10 分（每张 2 分，最多 10 分）。匹配质量为
`max(0, 1 - 平均指纹距离 / 原识别阈值)`；缺少证据的部分记 0 分。
运行匹配质量不等于识别正确率，不会自动生成“人工确认”标签。
“离线验证通过”指已用其他对局的人工确认样本验证，不代表通过实战验证。
运行匹配次数为 0 时显示“无匹配记录”；匹配次数增加也不等于证明识别正确。

后台使用其他对局中人工确认的样本验证：至少有独立正样本命中、新增识别覆盖、其他卡牌对照，
且无误认，才有资格被选用。同卡合格候选取最高分；同分优先保留当前使用项，再按独立正样本数、指纹 ID 排序。
选中后补库汇总结果显示“当前使用”，运行时该卡只加载这一条补库指纹。
尚无合格项、旧选用记录无验证证据或已被撤销时，不加载这些指纹，继续使用原库。
新标注暴露误认后会停止使用原选中项，并在剩余合格候选中重新择优。
新标注暴露误认或来源卡名变更后会停用候选。原始库不被覆盖。

运行观察在内存累加，后台采样线程约每 5 秒将有上限的聚合计数原子写入
`%APPDATA%/crX/card_samples/runtime-matches.json`，不在出牌线程逐次写盘。
界面约每 5 秒后台刷新评分和选用，本地库约 1 秒重新加载。需要启动新版程序；
旧进程不会自动加载新的 Python 逻辑。

## 按选择清空

“全选当前列表”只选择当前筛选及分组中显示的行，不扩展到其他列表。
“取消选择”清除当前选择，后台刷新不会自动重新选中；无选择时“清空选中”禁用。
待确认、全部中，“清空选中”仅删除选中的原始样本。
补库汇总中，选中行代表一个卡名及版本；清空会删除这些卡牌的全部候选，包括后台隐藏样本和当前使用指纹。
确认框列明所选卡牌、实际样本数量，以及是否涉及当前使用项；取消确认不执行删除。
删除范围在确认前固定，后台仅处理这个明确的样本集合，不按卡名追加后来出现的样本。
汇总行“撤销”会停用该卡全部候选，避免只撤销代表样本后又自动换成另一隐藏候选。
清空会删除对应截图、标注、导出文件、关联本地指纹和运行匹配计数；同一对局中未选中的其他行保留。
多个样本共用同一指纹时，关联指纹一并删除，其余样本文件和标注保留，可重新试用。
共享的离线预览报告因包含已删图片而作废，界面继续从保留记录读取。
运行中禁用清空，后台删除前检查目录、链接和文件归属。空列表不执行删除。

验证使用临时目录，覆盖未合格指纹不得加载、高分不越过验证门槛、每卡一个且版本独立、误认停用并切换合格备用、
评分与最高分选择、验证原因、后台统计落盘、按选择清空且保留未选中记录、异常路径拒绝删除，
以及实际 Tk 控件中的确认后自动验证、分组排序和撤销。
本次没有删除用户现有样本，没有启动真实游戏对局验证新评分。
