# 恢复前异常流程

运行过程中某个步骤失败、即将进入恢复时，程序会尝试保存当前失败界面和诊断信息。
覆盖商店、选择模式、卡组切换、开始对战、战斗、战后返回及恢复本身的运行失败。
达到连续恢复上限而停止的最后一次失败也会留样；正常达到局数上限或主动停止不会额外生成失败样本。

## 保存位置和内容

异常流程在工程旁的日志目录中：

```text
D:\DaYe\crXlogs\failures\日期时间-编号\
    frame.png       恢复前截图；截图失败时可能没有此文件
    failure.json    时间、失败步骤、原因、恢复序号、运行信息和对应日志位置
    review.json     人工备注及处理状态，独立保存，不修改原始证据
```

战后返回超时或达到操作上限时，保留导致失败判断的最后一帧，以及当时识别的阶段、
已执行操作数和时间上限，不再另截一张可能已经变化的页面。
其他步骤失败时，在重启前最多等待 2 秒尝试截图，超时或截图异常则只保存诊断信息和截图错误。
迟到的截图不会当作恢复前证据写入，避免误存已经重启后的画面。
异常堆栈最长保留 8000 字符，不复制整份运行配置。
截图以无损 PNG、BGR 解码顺序保存；异常分辨率也能保留以排查模拟器配置问题。

## 程序内查看和处理

“异常流程”标签页每 5 秒后台刷新，标题中的数字表示待处理数量。
可按待处理、已处理、已忽略或全部筛选，查看失败截图、详细原因、恢复序号和对应日志位置。
“放大截图”或双击预览可在单独窗口查看较大的画面；“打开样本目录”打开选中记录所在目录。

可以填写备注，标记已处理、忽略或恢复待处理。
这些操作只记录人工处理状态，不会自动增加识别规则、执行截图中的按钮或暂停任务。
确认是新弹窗或漏识别后，仍需补充识别及回归验证。

## 对运行的影响与边界

截图只发生在失败后、恢复前，不额外改变正常对战流程或局数计数。
编码和写盘由后台线程处理，队列最多 8 条；每次任务退出最多等待后台收尾 2 秒。
整个异常目录最多 200 条、128 MiB，达到任一上限后跳过新样本并记日志，不自动删除旧样本。
磁盘、权限或采样错误不会阻止原有恢复；日志会说明保存失败或容量已满。
强制终止工作进程可能中断尚未完成的后台写入，已有完整记录仍可查看。

功能测试使用明确标记为“功能验证”的模拟失败，不会为验证而重启正在运行的游戏。
测试覆盖最后失败帧一致性、截图超时及迟到结果丢弃、无截图时的文字诊断、容量与磁盘错误、
每次重启前采样及第五次失败后停止、备注持久化和界面查看；不把模拟超时描述为实机故障。
