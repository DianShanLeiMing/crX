# 实战卡牌采样与补库

2026-10-17：在现有手牌检查位置接入诊断采样。识别阈值仍为 1000，低分差仅作为采样依据，
不改变未知牌的现有出牌行为，不修改每次启动的局数上限或计数方式。

## 实战采样

每场战斗开始后建立一个采样会话，普通出牌、随机出牌、1v1 和 2v2 共用手牌可用性检查入口，
与整局录制开关独立。检查可用手牌时复用同一张缓存的 419×633 BGR 截图，不另行截屏。

每秒最多检查一次诊断条件，对当前可用手牌记录：

- 距离超过阈值、返回 `UNKNOWN` 的牌；
- 第一与第二个不同卡牌候选的距离差小于 100 的牌。候选先合并同一卡牌的不同指纹／别名；
- 同帧显示至少 5 点圣水，却连续三次诊断检查没有可用手牌的异常。
  圣水不足的正常等待不会触发这一类样本，且不直接认定为识别算法错误。

实际选中卡牌的识别结果另设直接保存入口，不受每秒一次的观察节流影响：
一旦返回未知或候选分差过小，就尝试保存当前识别帧，仍受去重、队列和容量限制。
普通与随机出牌都经过这个入口，随机出牌只记录诊断结果，不据此调整出牌位置。
记录中的 `trigger` 区分 `selected_card` 和 `hand_observation`，便于核查漏采原因。

每条记录包含卡牌裁图、完整手牌区域、同帧原图，及位置、对战模式、相对时间、BGR 标记、
前三个候选及实际距离、匹配阈值、候选分差、可用性紫色像素计数和原始指纹。
`label` 始终为空，候选名称不自动成为标注，也不自动更新识别库。

采样使用后台线程编码 PNG 和写盘；队列最多 8 条，每局最多接收 32 条，按原因和相似手牌图去重。
默认样本根目录上限为 128 MiB，达到上限后跳过新样本，不删除已有样本。
磁盘错误记录到日志，继续执行战斗；战斗结束最多等待后台收尾 2 秒，随后原流程继续。
后台处理和样本清单生成都不会启动新对战，也不重置已完成局数。

Windows 默认目录为 `%APPDATA%\crX\card_samples\日期时间-会话编号\`：

```text
samples.jsonl          每个样本写入后即追加的元数据
sample-000-card.png    卡牌裁图；无可用手牌异常时为手牌区域
sample-000-hand.png    完整手牌区域
sample-000-frame.png   同一帧原图
index.html            战后按原因和候选分类排列的待标注清单
summary.json          保存、去重、丢弃和错误计数
```

没有异常样本时不创建空目录。用户强制终止工作进程时，已写入的 PNG 和 JSONL 保留，
尚在队列中的条目和最终 HTML 清单可能不完整。

## 补库与验证

### 在程序中处理样本

程序新增“卡牌样本”标签页，每 5 秒在后台读取已落盘的样本。标签页标题中的数字表示待确认数量，
不会弹出阻塞对话框或暂停对战；即使还有待确认样本，也按原配置继续执行剩余局数。
列表默认筛选待确认，也可查看已确认、已补库、已忽略或全部记录。

1. 选择样本，查看放大的卡牌裁图、同帧手牌、完整战斗截图及采样时的候选距离。
   候选结果不预填为确认卡名，避免把错误的最近候选当成标注。
2. 在“确认卡名”中搜索中文名或英文 ID，区分基础、觉醒和精英版本，填写备注后点击“确认卡名并保存”。
   当前从已有卡牌名录选择；名录尚未包含的新卡可通过“恢复待确认”保留备注，待扩充名录后再确认。
3. 切牌动画、遮挡等无效样本可以“忽略此样本”；误操作可通过“恢复待确认”撤销。
4. 确认卡名后可“导出补库候选”，在该对局目录生成 `sample-000-candidate.json`。
   导出会从原始 BGR 截图重新提取指纹；无可用手牌异常、不可用状态或缺失原图不能导出卡牌指纹。
   候选文件包含卡牌 ID、4×16 指纹和来源，并明确标记 `validated: false`。

标注单独原子保存到每局的 `annotations.json`，原始 `samples.jsonl`、截图及已有 `review.json` 不会被改写。
页面兼容读取既有 `review.json` 中的确认和补库记录；新标注覆盖该样本的旧处理状态。
原有静态 `index.html` 不会随界面标注重写，处理状态以程序页面为准。

“已确认 · 待补库”仅表示人已确认卡名，导出不会自动修改或加载识别库。
仍需按下面的流程用其他画面验证，再将合格指纹加入源码；更新后重新启动任务生效。
文件扫描、图片读取、保存和导出均在后台线程进行，Tk 控件只在界面线程更新。

### 指纹入库

先检查清晰、稳定、确实可用的手牌，再确认卡名及觉醒／精英状态。
切牌动画、遮挡、不可用灰态不能直接拿来增加正常状态的指纹。
补充指纹集中在 `crX/bot/card_data.py` 的 `CARD_FINGERPRINT_VARIANTS`，保留原有数据与卡牌 ID，
同一卡牌允许多个实采指纹。新指纹随源码更新后生效，当前战斗中不热更新或自动训练。

本批补库包含亡灵巨人和觉醒加农炮：

- 参考来自 MuMu 实例 0、419×633、160 DPI 的实际练习战斗手牌，不使用游戏回放布局。
- 两张不同时间的验证帧中，旧库最近候选均为特斯拉，距离 2080／2178，因此返回 `UNKNOWN`。
- 追加亡灵巨人原生指纹后，距离降至 210／52，正确返回 `minion_giant`。
- 同手的小王子、加农炮、野蛮人滚桶及原有四张 BGR 回归手牌保持正确识别。
- 验证截图只保留手牌区域，位于 `tests/fixtures/card-hand-native-zh-*.png`；
  参考帧与验证帧来自不同时间，但仍属于同一场练习，不代表其他位置或模式已经充分验证。

最初蓝色样本被误标为飞龙宝宝，现已通过游戏的卡牌信息页确认其名称为“亡灵巨人”，
并与[官方亡灵学院公告](https://supercell.com/en/games/clashroyale/zh-hans/blog/release-notes/%E5%85%A8%E6%96%B0-%E4%B8%BB%E9%A2%98%E5%AD%A3-%E4%BA%A1%E7%81%B5-%E5%AD%A6%E9%99%A2/)
和[英文公告 Minion Giant](https://supercell.com/en/games/clashroyale/blog/release-notes/new-season-minion-academy/)核对。
旧的飞龙宝宝指纹未替换；新增 `minion_giant` 名称与分组，沿用气球兵、熔岩猎犬等已有的 `bridge_line` 落点。

觉醒加农炮来自后续实时练习的真正未知样本：原最近候选为戈仑冰人，距离 2014，超过识别阈值。
补库后参考样本返回 `evo_cannon`；另一时间帧原最近距离为 1998，补库后为 34。
觉醒加农炮使用已有 `defense_building` 分组，不新增战术逻辑。
回归图片为 `tests/fixtures/card-evo-cannon-native-zh.png`，仅保留手牌区域。

本次审计还发现 11 条上游指纹的每个分区总量为 100，而当前提取的总量为 891 像素，
其单位不同，需要真实样本校准。暂未直接将这些数据放大替换。
先前只有出牌分组、没有指纹的觉醒／精英 ID，也需要逐一收集真实画面，不能据基础版凭空生成。

回归覆盖同帧复制、BGR 一致、去重、容量上限、磁盘失败、队列满时不阻塞、异常退出收尾，
以及普通／随机两条战斗路径的会话生命周期。已有局数限制测试继续覆盖按配额停止、
失败不消耗局数和归档失败时不多开一局。
